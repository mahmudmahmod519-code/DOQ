# ربط موقع دوق بالتطبيق وتشغيل البيئات

## شكل الربط

الموقع والتطبيق لا يحتاجان خادمين منفصلين

```text
المتصفح أو تطبيق الهاتف
            │ اتصال HTTPS
            ▼
النطاق الرئيسي نفسه
            │
            ▼
خادم Caddy للشهادة والتوجيه
            │ شبكة Docker داخلية
            ▼
خادم دوق Node.js
       ├── صفحات الموقع
       ├── واجهات API
       ├── المصادقة والجلسات
       └── الإشعارات والمهام الدورية
            │
            ▼
قاعدة MySQL داخلية
```

لو أصبح التطبيق هاتفاً أصلياً بعد ذلك فسيستخدم نفس النطاق ونفس واجهات API

```text
https://example.com/auth
https://example.com/orders/api/v1
https://example.com/notifications/api
```

الموقع الحالي يعمل كـ تطبيق ويب تقدمي. هذا يعطي تثبيتاً على الهاتف وشاشة مستقلة من غير نسخة بيانات ثانية. ملفات التطبيق موجودة في `public/manifest.webmanifest` و `public/sw.js` و `public/app-client.js`

## دخول لوحة الإدارة

لوحة الإدارة جزء من نفس الموقع وتعمل من خلال المسار التالي

```text
https://example.com/admin
```

التحكم في المسار يعتمد على الدور الموجود في الجلسة. حساب الإدارة فقط يصل إلى لوحة الإدارة. تطبيق الهاتف يستخدم نفس الخادم لكن لا يحصل على صلاحيات إضافية بسبب كونه تطبيقاً

## بيئة التطوير

انسخ القالب إلى ملف محلي لا يدخل في Git

```powershell
Copy-Item .env.development.example .env.development
```

شغل قاعدة البيانات والتطبيق

```powershell
docker compose --env-file .env.development -f docker-compose.yml up --build
```

أو شغل Node مباشرة بعد وضع قاعدة البيانات المحلية على القيم الموجودة في الملف

```powershell
$env:DOQ_ENV_FILE='.env.development'
npm start
```

## بيئة الإنتاج

انسخ قالب الإنتاج خارج المستودع واملأه من مدير أسرار الخادم

```powershell
Copy-Item .env.production.example .env.production
```

عدّل اسم النطاق في ملف الإنتاج ثم شغل طبقة الإنتاج

```powershell
docker compose --env-file .env.production -f docker-compose.yml -f docker-compose.production.yml up -d --build
```

في الإنتاج قاعدة البيانات غير منشورة على الإنترنت والتطبيق لا يفتح منفذاً عاماً. خادم Caddy هو المنفذ العام الوحيد ويتولى HTTPS تلقائياً بعد توجيه النطاق إلى عنوان الخادم

ملف الإنتاج يستخدم أوامر دمج Compose لإزالة المنافذ وملفات البيئة الموروثة. استخدم إصداراً حديثاً من Compose يدعم علامات إعادة الضبط والاستبدال

## شروط التشغيل قبل النشر

1. اسم نطاق حقيقي يشير إلى عنوان الخادم
2. قيم سرية طويلة وفريدة لقاعدة البيانات و `JWT_SECRET`
3. بريد SMTP إنتاجي لإرسال استعادة كلمة المرور والتقارير
4. حساب Paymob وقيمه إذا كان اشتراك الشيف سيتم تحصيله إلكترونياً
5. اختبار نسخة احتياطية واسترجاعها قبل استقبال طلبات حقيقية
6. تغيير أي أسرار قديمة ظهرت في تاريخ Git قبل رفع المستودع

القالب لا يحتوي على أي كلمة مرور أو مفتاح فعلي

## ملاحظة عن التطبيق الأصلي

الجزء الموجود الآن يثبت اتصال الموقع والتطبيق من خلال تطبيق الويب التقدمي. لم يتم إنشاء حزمة Android أو iOS أصلية ولم يتم نشرها على المتاجر حتى الآن. إنشاء حزمة أصلية سيكون مرحلة لاحقة تستخدم نفس النطاق وواجهات API وتحتاج اختباراً على مسار التوزيع الفعلي لكل متجر

## حسابات الاختبار لكل دور

السكريبت ينشئ حسابا واحدا لكل دور في بيئة التطوير فقط. حساب الشيف وحساب شركة الدليفري يبدأان بحالة انتظار موافقة الأدمن. حساب العميل وحساب الأدمن يبدأان بحالة مفعلة

```powershell
$env:DOQ_ENV_FILE='.env.development'
$env:DOQ_ALLOW_TEST_ACCOUNTS='true'
$env:DOQ_TEST_PASSWORD='ضع كلمة مرور اختبار طويلة هنا'
npm run bootstrap:test-accounts
```

الحسابات التي ينشئها السكريبت هي البريد الإلكتروني فقط. كلمة المرور لا تحفظ في المشروع ولا تظهر في السجل. لا تستخدم هذه الحسابات على خادم الإنتاج

```text
doq-test-customer@example.test
doq-test-chef@example.test
doq-test-delivery@example.test
doq-test-admin@example.test
```

السيناريو المختصر للاختبار هو تسجيل العميل وإنشاء طلب ثم دخول الشيف بعد موافقة الأدمن ومراجعة الطلب ثم دخول شركات الدليفري وقبول أول شركة بالعربية الخاصة بها ثم إكمال الطلب. بعدها يراجع الأدمن الإشعارات والتقرير اليومي. إذا كان التحقق بخطوتين مفعلا لحساب فيجب إكمال صفحة الرمز قبل فتح اللوحة


ملف النقل يستبعد الأسرار وقاعدة البيانات المحلية والمجلدات المؤقتة والحزم المثبتة. بعد فك الضغط شغل `npm ci` ثم انسخ قالب البيئة إلى ملف محلي واستخدم Docker أو قاعدة MySQL موجودة

```powershell
powershell -ExecutionPolicy Bypass -File scripts\pack-transfer.ps1
```

ملف النقل الناتج يكون بجانب مجلد المشروع باسم `doq-project-transfer.zip`. لا تنقل ملف البيئة المحلي ولا مجلد `node_modules`

## نطاق المراجعة الأمنية الحالية

تمت مراجعة حماية تزوير الطلبات عبر رمز مرتبط ببذرة الجلسة مع استثناء مطابق تماما لمسار إشعار الدفع ثم تم تضييق استثناء المسار. استعلامات البيانات المستخدمة في الفلاتر تعتمد على معاملات وقائمة موارد ثابتة. مخرجات الواجهة التي تعرض بيانات من API تستخدم الهروب قبل إدخالها في HTML في المسارات التي تم إصلاحها. أسماء ملفات الرفع أصبحت عشوائية من الخادم ولا تعتمد على اسم العميل. صفحة الاختبار لا تظهر في الإنتاج

اختبار قاعدة البيانات والتدفق الكامل بين الأدوار يحتاج تشغيل MySQL فعلي. إذا لم تكن قاعدة البيانات متاحة فنتيجة الاختبار تظل غير مكتملة ولا تعتبر نجاحا للتشغيل الكامل
