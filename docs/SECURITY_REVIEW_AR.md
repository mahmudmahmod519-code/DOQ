# مراجعة الأمان والاختبار الحالية لمشروع دوق

## النتيجة

تم تنفيذ مراجعة مصدرية واختبارات آلية على طبقة الخادم والواجهات وقواعد الحماية

النتيجة الحالية هي أن الاختبارات الآلية ناجحة بالكامل. اختبار قاعدة البيانات والتدفق الكامل بين الأدوار لم ينفذ بعد لأن بيئة الفحص الحالية لا تحتوي على خادم MySQL أو MariaDB يعمل

## ما تم إصلاحه

- حماية CSRF أصبحت مرتبطة بالجلسة وموقعة ولا يوجد استثناء إلا لمسار إشعار الدفع المطابق تماما
- إشعار الدفع يتحقق من توقيع Paymob باستخدام مقارنة ثابتة الزمن ويمنع إعادة تنفيذ الحدث بسجل مستقل
- الدفع الإلكتروني متوقف افتراضيا من خلال PAYMENTS_ENABLED ولا يتم استدعاء Paymob ولا يتم فحص الاشتراك عند تعطيله
- مسارات المطبخ والطبق لا تعرض رقم المطبخ أو أي وسيلة تواصل خارجية للعميل
- محادثة الطلب داخل المنصة تمنع الروابط والبريد وأرقام الهاتف ووسائل التواصل الخارجية
- تفعيل الاشتراك من إشعار الدفع مقصور على حساب الشيف
- أسماء ملفات الرفع يولدها الخادم ولا تعتمد على اسم الملف المرسل
- صور الواجهات التي تأتي من API تمر عبر دالة تقبل نفس الموقع أو HTTPS فقط
- النصوص القادمة من API تهرب قبل إدخالها في HTML في المسارات التي تمت مراجعتها
- صفحة الاختبار غير متاحة في بيئة الإنتاج
- إنشاء حسابات الاختبار محمي ببيئة التطوير ومتغير تشغيل وكلمة مرور محلية ولا يطبع كلمة المرور
- الاستعلامات الديناميكية تستخدم قائمة موارد ثابتة ومعاملات مربوطة بدلا من تركيب قيم المستخدم داخل SQL
- ملف النقل يستبعد ملفات البيئة المحلية وقاعدة البيانات وملفات الاعتماد و node_modules وملفات الرفع

## الاختبارات التي نجحت

- 41 اختبارا ناجحا ولا يوجد اختبار فاشل أو متخطى
- فحص تحميل التطبيق وكل المسارات
- فحص تحليل كل ملفات JavaScript
- فحص سلامة النص العربي ومنع علامات الاستبدال والتشويه
- فحص CSRF والرموز الموقعة ومنع تجاوزها بواسطة Bearer غير موثق
- فحص HMAC الخاص بالدفع
- فحص منع حقن HTML في رسائل الخطأ والبيانات المعروضة
- فحص صلاحيات الأدوار وحسابات الاختبار
- فحص عدم كشف بيانات العميل في واجهات المطبخ والدليفري
- فحص عدم وجود تخفيف مصطنع للاختبارات
- فحص تجميع ملف النقل بدون أسرار أو node_modules

## ما لم يتم إثباته بعد

- تسجيل الدخول الحقيقي لكل حساب
- إنشاء طلب حقيقي من العميل ثم قبوله من الشيف ثم منافسة شركات الدليفري ثم التسليم
- تدفق التحقق بخطوتين مع تطبيق مصادقة فعلي
- تشغيل الترحيلات على قاعدة MySQL فعلية
- تشغيل Cron والبريد و Paymob في بيئة خارجية
- اختبار المتصفح والهاتف على نسخة منشورة

هذه البنود ليست فشلا في الاختبارات الحالية. هي فحوص تشغيلية معلقة إلى أن تتوفر قاعدة بيانات تشغيلية وبيئة تشغيل كاملة

## حسابات الاختبار

السكريبت ينشئ حسابا واحدا لكل دور بطريقة إنشاء فقط. حساب الشيف وحساب الدليفري يبدأان في حالة انتظار موافقة الأدمن. كلمة المرور لا توجد في المستودع ولا تظهر في السجل وتحدد محليا من متغير البيئة

الأدوار المغطاة هي العميل والشيف والدليفري والأدمن

## قرار الجاهزية

المشروع جاهز من ناحية الاختبارات المصدرية والحواجز الأمنية التي أمكن إثباتها محليا

المشروع غير معلن كجاهز للإطلاق النهائي قبل تشغيل فحص قاعدة البيانات والتدفق الكامل على نسخة منفصلة مع بيانات اختبار ثم إعادة اختبار مسار المتصفح والتطبيق
